# README 写作规范——唯一权威

> 生成或更新项目 README 时**只读本文件**。README 与 ZHIDAO.md 是配套产物但定位不同：README 是"项目门面"（给访客看，30 秒决定要不要深入了解），ZHIDAO.md 是"项目地图"（给开发者看，通读代码用）。

## 1. 定位区别（必须分清）

| 维度 | README.md | ZHIDAO.md | Description.md |
|---|---|---|---|
| 读者 | 项目访客 / GitHub 浏览者 / 接手评估者 | 要通读源码的开发者 | 列表浏览者 / 搜索者 |
| 篇幅 | 50-150 行（精简） | 300-800 行（详尽） | 300-350 字符（中英各一版） |
| 深度 | 是什么 / 怎么用 / 技术栈 | 为什么 / 机制 / 逐文件导读 | 是什么 + 技术栈（3-5 句） |
| 场景 | GitHub 首页 / 项目门面 | 开发者通读代码 | GitHub About / 卡片 / 简历 / 搜索摘要 |
| 格式 | Markdown | Markdown | 纯文本（无 markdown 语法） |
| 位置 | 项目根目录（覆盖或追加） | 项目根目录（新建） | 项目根目录（新建） |

> Description.md 的详细规范见 `description-guide.md`。

## 2. 结构：7 章模板

| # | 章节 | 内容要点 | 必需 |
|---|---|---|---|
| 1 | 项目名 + 一句话简介 | `# 项目名` + 一句话说清"这是什么、解决什么问题" | ✅ |
| 2 | 功能特性 | 3-5 条 bullet，每条一句话讲清核心能力 | ✅ |
| 3 | 快速开始 | 安装 + 运行，3-5 步命令，复制即用 | ✅ |
| 4 | 项目结构 | 精简目录树（只到二级），标注核心目录职责，末尾"详见 [ZHIDAO.md](ZHIDAO.md)" | ✅ |
| 5 | 技术栈 | 表格或 bullet 列出框架/语言/关键依赖 + 版本 | ✅ |
| 6 | 配置说明 | 关键配置项表格（名称-默认值-说明），无配置可省 | ⬜ |
| 7 | License | 项目 License 类型，无 License 可省 | ⬜ |

## 3. 文件头模板

```markdown
# {{项目名}}

> {{一句话简介：是什么 + 解决什么问题}}

{{可选：一行 badge 或 status 说明}}
```

## 4. 风格要求（必须遵守）

1. **30 秒原则**：访客打开 README，30 秒内能回答"这项目是什么、我能用吗、怎么跑起来"——做不到就砍内容
2. **命令可复制**：快速开始里的命令必须复制即用，含环境准备（如 `pip install -r requirements.txt`），不要写"参考文档"这种敷衍
3. **不展开实现细节**：README 是门面不是教程，"怎么实现的"交给 ZHIDAO.md；README 只回答"是什么"和"怎么用"
4. **中文为主，术语中英对照**：与 ZHIDAO.md 风格一致，`Agent（智能体）`、`Graph（图）`
5. **结构表是主角**：目录树用 ASCII，配置项用表格，技术栈用列表——信息密度来源
6. **指向 ZHIDAO.md**：项目结构章节末尾必须有"详细架构与代码导读见 [ZHIDAO.md](ZHIDAO.md)"

## 5. 已有 README 的处理策略（重要）

目标项目已有 README 时，**绝不覆盖**：

| 情况 | 处理 |
|---|---|
| 用户明确要"重写 README" | 先告知将覆盖的内容，用户确认后整体重写 |
| 用户要"更新 README" / "补全 README" | 保留原有内容，只补缺失章节、更新过时信息；新增内容用 `<!-- CC: 新增 -->` 标记 |
| 已有 README 且用户没提 README | 不动，只生成 ZHIDAO.md |

**红线**：绝不在用户没要求的情况下擅自改 README.md。

## 6. 数据来源

- **项目名 / 一句话简介**：从 `extract_skeleton.py` 的 `project_root` + README（若已有）+ ZHIDAO.md（若已生成）综合判断
- **功能特性**：从 skeleton.json 的 `modules` + `dependency_links` 入度最高的文件推断核心能力
- **快速开始**：从构建标志文件（pom.xml / package.json / requirements.txt / go.mod 等）推断安装与运行命令
- **项目结构**：从 skeleton.json 的 `modules` 生成精简目录树
- **技术栈**：从 skeleton.json 的 `language_hint` + 构建标志文件 + imports 推断

## 7. 质量验收（生成后自检）

- [ ] 7 章齐备（第 6/7 章视项目情况可省）
- [ ] 一句话简介能让外行听懂"这是什么"
- [ ] 快速开始的命令复制即用
- [ ] 项目结构指向 ZHIDAO.md
- [ ] 篇幅在 50-150 行（超出说明写太细，砍）
- [ ] 已有 README 时未被覆盖（除非用户明确要求重写）
