# 代码注释规范——唯一权威

> 生成任何代码注释时**只读本文件**（语言语法另见 `language-adaptation.md`），风格把握不准时对照三套黄金样例：`samples/Gewu-Deep-Research/`（Agent 编排型项目：子图/工具调用/状态流转）、`samples/Code-Probe/`（业务服务型项目：RAG 检索/SSE 流式/会话持久化）与 `samples/Mall-Order/`（Java Spring Boot 业务服务型项目：Controller/Service/Mapper 分层、幂等与防超卖、状态机 CAS、接口与实现的注释分工、MyBatis SQL 意图注释）。
> 本文件融合三层：**用户黄金风格**（默认采用，拟人化比喻等）+ **通用底线**（意图级 vs 流水账）+ **正反例速查**。

## 1. 底线：意图级 vs 流水账

**核心判据：注释里必须包含代码本身读不出来的信息**（为什么 / 业务语义 / 隐藏约束）。删掉注释后读者信息零损失 → 就是废话，删。

| 级别 | 特征 | 判定 |
|---|---|---|
| 流水账（禁止） | 复述代码行为：`// 调用 pay` `// 金额设为 100` | ❌ |
| 意图级（目标） | 解释为什么、业务语义、调用前提、失败后果 | ✅ |

## 2. 用户黄金风格（默认采用）

### 2.1 整体原则

1. **双语并存**：保留源码原有英文 docstring / Javadoc 不动，中文意图注释加在 docstring **之前**或关键行上方，不删不改原文
2. **每个函数必须有"一句话职责"**：格式 `# 函数名（中文名）：职责一句话`，后面可跟机制展开
3. **拟人化比喻降低理解门槛**：把架构角色映射到人类组织（总导演、项目经理、小兵、快递箱、模具、哨兵）
4. **解释"为什么"和"机制"**，不只"是什么"

## 3. 注释粒度与红线

### 3.1 粒度

- **类注释**（必需，1-4 句）：核心职责、关键不变量、线程安全说明
- **方法注释**（必需，1-5 句）：做什么 + 参数/返回值约束 + 副作用 + 异常抛出条件
- **行内注释**（按需）：仅在非显而易见逻辑处——状态机流转、复杂条件、workaround、性能关键路径、并发/事务边界、魔数
- **禁止**：为每个字段、每个简单赋值、每个 if 分支加注释（信号稀释）

### 3.2 与已有注释的关系（红线）

- 已有注释**一律保留**，禁止覆盖/改写/删除
- 已有注释质量差时：保留原文，下方追加意图级注释并用 `[补充]` 前缀标注
- 新增注释避免与已有注释重复表达同一信息

### 3.3 不编造：遇到读不懂的代码（红线）

意图级注释的基础是"真懂业务"。若读不懂某段代码的业务背景、无法确认其设计动机：

- **禁止**臆测、编造、套用看似合理的业务故事
- **必须**写明"待确认"标记，留待负责人核实：

```python
# 待确认：此处逻辑疑似处理支付超时回滚，但未找到对应业务文档，
# 也未在调用方看到事务边界标注，需与支付组负责人核实后补全意图。
```

- 待确认标记不占用黄金风格额度，**不算注释完成**，需在 Validation 阶段汇总报给用户
- 宁可标"待确认"也不要写一段似是而非的故事——错误的意图注释比没注释更有害

### 3.4 语言与格式

- 注释语言跟随用户请求（默认中文）；标识符/类型名/异常名保留原文
- 术语统一：同一概念全项目同一译名
- 单行注释 `//`（Java/JS/TS/Go/C 系）或 `#`（Python）；块注释 `/** */` / `"""docstring"""`（语法细则见 `language-adaptation.md`）
- `//` 后加一个空格；行内注释与代码间留 1-2 空格

## 4. 特殊场景规则

- **状态机/流程编排**：每个状态转换处注释：`// 状态: PENDING -> PAID，触发条件: 支付回调成功`；注明下一可能状态
- **事务/锁**：事务边界、加锁处注明原子性范围与回滚后果：`// [事务] 锁订单 + 扣库存 + 写流水必须原子，任一失败整体回滚`
- **外部 RPC/HTTP**：注明服务名、超时、重试、失败补偿：`// 调用支付网关（超时3s，重试2次），失败仅记录不阻塞主流程`
- **异步/回调**：注明线程模型：`// 由支付回调线程执行，勿在此直接操作共享可变状态`
- **性能关键路径**：`// 热点路径，禁止在此添加日志/反射，每请求调用 1000+ 次`
- **Workaround**：`// [Workaround] 网关返回 500 时重试一次规避其限流误报，上游修复后应移除`
- **疑似缺陷**：只标注不改动：`// [注意] 潜在 NPE：order 可能为 null（见 OrderService#getById 空返回分支）`

## 5. 正反例速查

### 5.1 反例（流水账，一律禁止）

```java

    // 调用 find 方法查订单
    PaymentRecord record = paymentMapper.findByOrderNo(request.getOrderNo());
    // 如果 record 为空
    if (record == null) {
        // 创建新订单

    }
    // 返回已存在订单
```

### 5.2 正例（意图级，目标形态）

```java

        // 已支付/处理中的订单不允许重复发起，与网关侧 dedup_key 双保险

    PaymentResult result = paypalGateway.charge(request);
    ...
```
