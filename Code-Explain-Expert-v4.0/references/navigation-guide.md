# 导航文档规范（ZHIDAO.md）——唯一权威

> 生成项目导航文档时**只读本文件**，风格把握不准时再对照 `samples/ZHIDAO.md`（用户认可的黄金样例）。
> 本规范以用户认可的 10 章黄金模板为主体，同时保证覆盖通用模板的技术栈/目录树/模块职责/依赖流向/阅读路径五要素（映射关系见 §1.2）。

## 1. 结构：10 章黄金模板

### 1.1 章节骨架

| # | 章节 | 内容要点 |
|---|---|---|
| 1 | 这个项目是干什么的？ | 一句话总结 + ASCII 流程 + 类比解释（"不是一个 X，而是一个 Y"） |
| 2 | 核心概念速览 | 读者读代码前必须先懂的概念；每个概念：是什么 + "把它理解为…"类比 + 伪代码 |
| 3 | 项目目录结构详解 | 带注释的目录树（`# 职责` 行内标注，⭐🔐🧪📋 emoji 标记重点） |
| 4 | 运行流程全景图 | 大型 ASCII 流程图，分阶段，每个节点框内写职责 + 退出条件 |
| 5 | 逐文件代码导读 | 每个文件：文件作用 / 阅读顺序建议 / 关键数据结构表 / **要点**小结 |
| 6 | 关键设计模式解析 | 架构图（ASCII）+ 每个模式的意图 + 代码片段 |
| 7 | 配置系统详解 | 配置项表格（名称-默认值-说明）+ 加载优先级 |
| 8 | 如何运行和测试 | 步骤式命令：环境准备 / 启动 / 评估 |
| 9 | 复刻建议与学习路线 | 分阶段路线（每阶段：做什么 + 耗时估计），附学习资源表 |
| 10 | 常见问题 | Q&A 形式，回答"为什么"类问题 |
| 附录 | 关键术语对照表 | 英文-中文-说明三列表 |

### 1.2 通用五要素在 10 章中的落点

| 通用模板要素 | 落在第几章 |
|---|---|
| 技术栈识别 | 第 1 章一句话 + 第 3 章目录树配置项 + 第 8 章运行环境 |
| 目录树 | 第 3 章 |
| 模块职责 | 第 3 章 + 第 5 章逐文件导读 |
| 依赖流向 | 第 4 章全景图 + 第 6 章设计模式 |
| 推荐阅读路径 | 第 5 章"阅读顺序建议" + 第 9 章学习路线 |

### 1.3 文件头模板

```markdown
# 📖 {{项目名}} 项目导读指南

> 本文件是 `{{项目名}}` 项目的中文导读，帮助你从零开始理解这个 {{系统类型}} 的架构、代码和运行方式。
```

## 2. 风格特征（必须模仿）

1. **标题带 emoji**：`# 📖 <项目名> 项目导读指南`
2. **表格是主角**：数据结构、配置项、函数清单、提示词清单一律用表格（列对齐），这是信息密度来源
3. **ASCII 图不止装饰**：流程图必须包含每个节点的职责说明、分支条件、退出条件
4. **阅读顺序建议**：逐文件导读中给出"先读 X 再读 Y"顺序，标注行号范围（如 ~60、~700-718）与耗时估计（约 15 分钟）
5. **新手友好类比**：复杂概念用生活化类比（"有向图执行引擎""Agent 是 LLM + 工具"），不默认读者懂框架
6. **"要点"小结**：每个文件/小节末尾用 `**要点**：` 提炼 2-4 条关键信息
7. **中文为主，术语中英对照**：`Agent（智能体）`、`Subgraph（子图）`
8. **目录带锚点**：章节标题用 `## 1. 标题` 格式，目录链接可跳转

## 3. 质量验收（生成后自检）

- [ ] 第 4 章全景图每个节点标注职责与退出条件
- [ ] 阅读路径带行号与耗时估计
